目前 OCR pipeline：PDF 放入 data/sources 後會經過甚麼
=======================================================

適用日期：2026-07-29
範圍：目前鎖定的 DSE MATH CP Paper 2 MCQ 路徑，以及一般 PDF 的預設路徑。

先記住一點
------------

把 PDF 放進 data/sources/ 不會自動開始處理；必須執行命令或 batch script。
PDF 的檔名（去掉 .pdf 後、經 safe stem 正規化）會成為 doc_id，例如：

    data/sources/2022p2.pdf  ->  doc_id = 2022p2

主要目錄
--------

    data/sources/<doc_id>.pdf             原始 PDF
    data/pdf_pages/<doc_id>/page_001.png  每頁影像
    data/pdf_pages/<doc_id>/layout.json   可重用的版面／題目框契約
    data/pdf_pages/<doc_id>/crops/         DSE MCQ 專用題目 crop
    output/crops/                          Stage2 實際送入 OCR/VLM 的 crop
    output/<doc_id>.*                     最終文字、TeX、PageIR、quality

簡圖
----

    PDF 放入 data/sources/<doc_id>.pdf
                    |
                    v
          [1] PDF rasterize（每頁變 PNG）
                    |
                    v
       +------------+-------------+
       |                          |
       v                          v
  DSE Paper 2 MCQ             一般 PDF
  專用題目框路徑               預設一般版面路徑
       |                          |
       v                          v
  RapidOCR 行文字              MinerU layout blocks
  + 題號/A-D 規則               (TEXT / FORMULA / FIGURE ...)
       |                          |
       +-----------+--------------+
                   v
      layout.json / LayoutBlock（每個可 OCR 的區域）
                   |
                   v
      crop PNG -> Qwen3-VL Stage2 OCR（按 block）
                   |
                   v
      stitch -> Stage3 -> PageIR -> txt / tex / quality


=======================================================
一、DSE MATH CP Paper 2 MCQ：目前應使用的專用路徑
=======================================================

這是本專案目前的 locked trunk。目標不是把一頁切成段落，而是：

    1 個選擇題 = 1 個 box = 題幹 + 圖（如有）+ A-D 選項

執行順序（新 PDF）
--------------------

1. pdf_to_images.py：PDF -> page PNG

    uv run python pdf_to_images.py data/sources/<doc_id>.pdf `
      --out-dir data/pdf_pages/<doc_id>

   程式：pdf_to_images.py
   作用：使用 PyMuPDF / fitz，以設定 DPI（通常 200）把 PDF 每頁輸出為
         data/pdf_pages/<doc_id>/page_001.png、page_002.png ...。

   補充：主 pipeline 的 LayoutAnalyzer.pdf_to_images() 也能做同一件事；
         cross_year_2012_2023.py 在沒有既存 PNG 時則呼叫 pdf_to_images.py。

2. scripts/dse_mcq_layout_doc.py：頁面 PNG -> 專用 MCQ layout.json

    uv run --with rapidocr-onnxruntime python scripts/dse_mcq_layout_doc.py `
      --pages-dir data/pdf_pages/<doc_id> `
      --pdf data/sources/<doc_id>.pdf `
      --out-dir data/pdf_pages/<doc_id> `
      --work-dir output/dse_mcq_layout_<doc_id> `
      --no-backup-layout

   這一步只做 light OCR、規則和 crop，不載入 Qwen3-VL，也不產生最終 txt。
   DSE 預設會跳過 page_001（考生須知／封面）；若第一頁真的有 MCQ，才用
   --include-first-page。

   這條子路徑涉及的 .py：

   scripts/dse_mcq_layout_doc.py
     - 批次處理每個 page_XXX.png。
     - 用 RapidOCR 取得每頁文字行及 bbox；儲存為
       output/dse_mcq_layout_<doc_id>/page_XXX.lines.json。
     - 輸出 page_XXX.overlay.png（紅／藍／綠框）供肉眼檢查，以及 summary.json。

   src/ocr_pipeline/dse_mcq_ocr.py
     - load_ocr_lines_json()：讀取已存的 light-OCR 行資料，讓 layout 可重播。
     - 正式 light OCR 由 dse_mcq_layout_doc.py 的 RapidOCR 實作處理。

   src/ocr_pipeline/dse_mcq_profile.py
     - 讀取 config/profiles/math_cp_p2.yaml。
     - 提供題號 pattern、A-D option pattern、padding、頁首 orphan 空間等 profile。

   src/ocr_pipeline/dse_mcq_region.py
     - 核心題目框演算法。
     - tag_lines() 把 light-OCR 行標成題號、選項、其他文字。
     - detect_mcq_regions() 以題號開題、A-D anchors 收束，找出每一題 bbox。
     - 修正 OCR 漏題號時的 orphan A-D、2020 Roman numeral 類誤讀、頁首題目與
       同頁左側題號 gutter；右側保留寬闊延伸，避免裁掉圖與右側選項。

   src/ocr_pipeline/dse_mcq_layout.py
     - 把每個 McqRegion 轉成一個 TEXT LayoutBlock。
     - 寫 data/pdf_pages/<doc_id>/crops/pNNN_qNNN.png 與 block meta.question_id。

   src/ocr_pipeline/layout_artifact.py
     - 寫入／讀取 data/pdf_pages/<doc_id>/layout.json。
     - 這是下一步 --reuse-layout 所讀取的共用契約。

   這一步完成後，應先檢查：

     - layout.json 是否每題 Q1--Q45 各一個、沒有 duplicate。
     - output/dse_mcq_layout_<doc_id>/ 的 overlay 是否把題號、題幹、圖、A-D 全包住。

3. run_ocr_pipeline.py：重用題目框，逐題做 VLM OCR

    uv run python run_ocr_pipeline.py data/sources/<doc_id>.pdf `
      --reuse-images --reuse-layout --output-tag mcq

   程式：run_ocr_pipeline.py
     - CLI 入口：讀 config/ocr_pipeline.yaml，建立 PipelineManager，再呼叫 run()。
     - --reuse-images：不重畫 PDF page PNG。
     - --reuse-layout：不跑一般 MinerU layout，直接讀上一步的 layout.json。
     - --output-tag mcq：輸出名稱使用 <doc_id>.mcq.*，避免覆蓋未加 tag 的結果。

   主流程：src/ocr_pipeline/pipeline.py 的 PipelineManager

     Stage1（此命令是 reuse）：
       - load_layout_artifact() 讀取 data/pdf_pages/<doc_id>/layout.json。
       - 每一個 LayoutBlock 已帶 question_id 和題目 bbox。

     Stage2 route：
       - self.router.route_page() 依序處理每一個題目 box。
       - 會先 crop 成 output/crops/pNNN_qNNN.png。
       - DSE 題目 block 有 meta.question_id，所以使用 MCQ_ROUTER_PROMPT。
       - 每題 crop 交給 Qwen/Qwen3-VL-8B-Instruct（4-bit）辨識。
       - 可選 Instructor shadow：若 structured_ocr.enabled=true，另把同一 crop
         送往 OpenAI-compatible endpoint，以 McqOcrResult 驗證結構；預設
         shadow_mode=true，不取代 Qwen Transformers 產生的正式 raw_text。

     Stage3（MCQ 預設 sanitize）：
       - DraftAssembler.stitch() 依 question_id 加上 "N." 和題目間空行。
       - FinalPolisher.polish_mcq() 預設不再叫 VLM 改寫；保留 Stage2 文字，
         只做 deterministic sanitize / Unicode-LaTeX 協助。
       - 原因：避免 VLM 在 page polish 時解題、丟 A-D 或把相鄰題黏在一起。

     Finalize：
       - content_first.finalize_content_first() 形成 PageIR、txt、tex 和 quality report。
       - _write_questions_jsonl() 為每個 question_id 寫一行 JSON。

   Stage2 / Stage3 相關 .py：

   src/ocr_pipeline/factory.py
     - 依 config 建立 Qwen VLM、MinerU layout engine、router、assembler、polisher。

   src/ocr_pipeline/routers.py
     - DynamicRouter.crop()：依 block bbox 裁圖。
     - TextRouter：DSE MCQ TEXT block 選 MCQ_ROUTER_PROMPT，呼叫 text engine。
     - MathRouter：一般 formula/equation block 走公式 OCR；DSE MCQ 是整題 TEXT box，
       因此由 TextRouter 一次讀完整題。

   src/ocr_pipeline/engines/vlm_text.py
     - VlmTextEngine.ocr()：把 crop + prompt 交給 VLM client。

   src/ocr_pipeline/vlm_client.py
     - 載入並呼叫 Qwen3-VL，實際模型推理在這裡。
     - build_mcq_structured_client() 只在設定啟用時建立 Instructor client；
       本機 4-bit Transformers backend 不會被 Instructor patch 或移除。

   src/ocr_pipeline/mcq_structured.py
     - Pydantic v2 McqOcrResult：stem、exact A-D、可見 figure labels、
       uncertain_tokens、warnings、requires_review。
     - question_id 不在 schema；必須取自 Stage1 block metadata。
     - render_text() 可把 validated result 穩定轉回既有 Stage2 純文字格式。
     - Instructor 使用 from_provider + response_model，最多一次 validation retry。

   src/ocr_pipeline/assemble.py
     - DraftAssembler：把逐題 Stage2 結果串成題號清楚、題間有空行的 draft。
     - FinalPolisher：MCQ 預設 sanitize；只有 config 改成 mcq_stage3: vlm 時才再用
       MCQ_POLISH_PROMPT 呼叫 VLM。

   src/ocr_pipeline/pylatex_assist.py、latex_math.py
     - 保留 CJK、處理 Unicode -> LaTeX 與常見數學／TeX 清理；不負責重新 OCR。


=======================================================
二、一般 PDF：未使用 DSE MCQ 專用 layout.json 的預設路徑
=======================================================

命令：

    uv run python run_ocr_pipeline.py data/sources/<doc_id>.pdf

此時 run_ocr_pipeline.py -> factory.py -> pipeline.py 的 Stage1 會走：

  1. LayoutAnalyzer.pdf_to_images()（src/ocr_pipeline/layout.py）
       PDF -> data/pdf_pages/<doc_id>/page_XXX.png

  2. MineruLayoutEngine（src/ocr_pipeline/engines/mineru_layout.py）
       從每張 PNG 找一般 layout blocks，例如 TEXT、FORMULA、TABLE、FIGURE。
       這是一般文件的 default；不是 DSE Paper 2 MCQ 的建議 regioner。

  3. layout_artifact.save_layout_artifact()
       寫 data/pdf_pages/<doc_id>/layout.json，供下一次 --reuse-layout。

  4. PipelineManager._release_layout()
       釋放 layout 模型 VRAM，才載入／使用 VLM；12 GB GPU 不可並行兩條 OCR pipeline。

  5. routers.DynamicRouter
       依 block type 裁圖與分派：TEXT/TABLE -> TextRouter；FORMULA/EQUATION ->
       MathRouter；FIGURE 預設保留 crop 而 skip OCR（config pipeline.skip_figures）。

  6. assemble.py 的一般 Stage3
       非 MCQ 頁可使用 VLM polish；MCQ 則仍受 sanitize 規則保護。

  7. content_first.py / segmenter.py / formula_integrity.py / quality.py
       轉為 retrieval-friendly PageIR、檢查數學片段、輸出最終檔與品質報告。


=======================================================
三、最終輸出與每個檔案的用途
=======================================================

假設使用 --output-tag mcq，doc_id=2022p2：

    output/2022p2.mcq.txt
      - 可直接人手校對／編輯的純文字 OCR 結果。

    output/2022p2.mcq.tex
      - LaTeX 包裝後的結果；可加 --check-compile 觸發 latexmk/xelatex compile。

    output/2022p2.mcq.pageir.json
      - PageIR；每頁有 segments，帶 kind、text、bbox、integrity、crop_relpath。
      - MCQ 設計上每題會 coalesce 成一個 segment。

    output/2022p2.mcq.quality.json
      - PageIR 結構品質指標及 verdict（pass/warn/fail）。
      - 注意：現時它不會自動驗證 Q1--Q45 是否齊全；正式 ingest 前要同時檢查
        layout.json 和 questions.jsonl 的 coverage。

    output/2022p2.mcq.questions.jsonl
      - MCQ 專用，一題一行：question_id、page、block_id、crop_path、text、
        structured_ocr。
      - text 保持向後相容；structured backend 未啟用或失敗時，
        structured_ocr 為 null。

    output/crops/pNNN_qNNN.png
      - Stage2 當次實際送去 VLM 的題目 crop。後續 rerun 可能覆寫同名檔。

    output/dse_mcq_layout_2022p2/page_XXX.lines.json
    output/dse_mcq_layout_2022p2/page_XXX.overlay.png
    output/dse_mcq_layout_2022p2/summary.json
      - layout debug artifacts：light-OCR 行、可視化題框、每頁 qid/數量摘要。

    output/<doc_id>.mcq.pdf / .log（僅 --check-compile 時）
      - compile_check.py 呼叫 latexmk 或 xelatex 產生的編譯結果／日誌。

操作安全提醒
------------

  - DSE MCQ 的正式路徑先檢查 overlay，再啟動 VLM Stage2；layout box 不正確時，
    不應浪費 GPU 直接 OCR。
  - 不要同時跑兩個 run_ocr_pipeline.py（RTX 4070 Super 只有 12 GB VRAM）。
  - N-up 現在固定為 nup.enabled: false。
  - Stage3 的 mcq_stage3 預設 sanitize；不要改回 VLM rewrite，除非特別要做受控實驗。
  - quality.json 的 pass 不是 formal ingest 的唯一條件；DSE MCQ 還必須人工／程式確認
    Q1--Q45 在 layout.json 與 questions.jsonl 都完整。
